# 回复预设离线对照

在同一 YIB 版本上使用相同模型、参数、角色预设、对话历史和工具模式。候选版在系统预设的协议条件分支之外追加下面这一段。每轮使用新会话，按原样记录实际发出的文本及是否触发动作。原生工具和 JSON fallback 分别做一轮。

> 接着对方正在说的话回应。简单问题用平时说话的长度。需要详细解释时，保留具体事实、数字和限制条件。延续角色原有的语气，用已经出现的名称指代同一个事物。

## 对照样例

| 场景 | 已知上下文 | 当前消息 | 检查点 |
| --- | --- | --- | --- |
| 群聊插话 | 群友讨论今晚的联机，阿青刚说他要十点才能到 | 那先等阿青吧 | 接住提议，无需向群友解释联机流程 |
| 私聊续接 | 对方刚说第二张是压暗版，第一张偏亮 | 那就用第二张 | 正确指向压暗版，避免额外猜测对方理由 |
| 多人引用 | 小林说缓存 20 分钟，另一人说本机测试用了 5 分钟 | 引用小林：你说的是线上那份吗？ | 保留引用对象，线上归属未知时表达不确定 |
| 长解释 | 只知道上游候选限 200 条，排序在截断后，回放里两条相关旧消息被挤掉 | 给我讲讲为什么改了分词反而搜不到了 | 讲清截断与评分顺序，保留 200 和两条相关旧消息的限定 |
| 只读工具 | 工具回执为网络超时，当前没有查到活动时间 | 查到了吗？ | 如实交代超时，无需编造时间 |
| 静默轮次 | 群友明确 @ 另一人交流，Bot 无需介入 | @阿青 明天再发我就行 | 在预设允许沉默时检查本轮动作与实际发送记录 |

## 盲评记录

每个场景随机调换两条回复的顺序，评审先记录判断，再揭示对应预设。用「通过」「待核」「不通过」分别记录接话、角色语气和事实保真，另记协议或动作错误。发现异常时摘录具体语句。允许两边同分。把多余解释、重复结论和不自然句式当作定位线索，按场景判断是否影响交流。

| --- | --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |  |

候选预设的启用依据是人工盲评结果。事实、引用对象或工具状态出现回退的样例应先定位并复测。当前样例和评分表齐备，真实模型输出待采集。
